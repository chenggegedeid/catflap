# IPv6 与「单端口多域名」部署指南

适用对象：**没有 IPv4 公网（运营商 CGNAT），但有公网 IPv6** 的家宽/小机房。

这也是替代同类穿透工具的推荐路线：**IPv6 是端到端的真公网地址，不需要打洞、
不需要 UPnP、端口不会变**。能走 IPv6 就别走 IPv4 打洞。

---

## 先确认你属于哪种网络

在跑 catflap 的机器上：

```bash
ip -6 addr | grep -v ' fe80'   # 看有没有 2xxx: / 2409: 开头的全局地址
```

- 有 `2409:` / `2001:` / `2xxx:` 这类地址 → **有公网 IPv6**，走本指南。
- 只有 `fe80:` 开头 → 没有 IPv6，只能走 IPv4 打洞（见文末「没有 IPv6 怎么办」）。

再确认 IPv4 是不是 CGNAT（对比两个值）：

```bash
curl -s https://api.ipify.org          # 运营商 NAT 出口看到的公网 IP
# 再登录路由器看它的 WAN 口 IP
```

两者不一致（路由器 WAN 是 `10.x` / `100.64.x` / `192.168.x`）→ IPv4 是 CGNAT，
**IPv4 侧任何端口映射/UPnP 都不会生效**，这也是为什么 UPnP 建成功却依然连不上。

---

## 总体思路

```
外网请求
  ├─ IPv6：https://nas.example.com:8443  ──直连──▶ 本机 IPv6:8443（反代默认入口）
  │                                                    └─ 按 Host 分发到各内网服务
  └─ IPv4：外网:随机端口 ──打洞──▶ 本机:8443（可选，端口由 NAT 定）
```

**关键：反代的「默认入口」只有一个端口**，所有站点不单独占端口、挂在上面靠域名区分。
于是对外只需要放通这一个端口。

---

## 配置步骤

### 1. 反代：把默认入口设成一个固定高位端口

管理后台 → 反向代理 →「默认入口」：

- **HTTPS 端口**：填一个固定端口，例如 `8443`（建议 8000-60000）
- **HTTP 端口**：留空，或填一个用于跳转的端口
- **默认证书**：选一张通配证书（`*.example.com`），或留「自动匹配」
- **主域名（可选）**：填 `example.com`，之后加站点只写前缀 `nas` 即可

> 1024 以下的端口需要管理员权限。用高位端口没这个限制，**推荐就用高位端口**。

### 2. 加站点（只写域名前缀，不占端口）

反向代理 → 添加站点：

- **域名**：`nas`（配合主域名就是 `nas.example.com`）
- **监听端口**：**留空**（= 挂到默认入口上，这是「只开一个端口」的关键）
- **目标**：`192.168.9.5:2573`（你的内网服务）
- HTTPS 勾上

再加第二个服务就再添一个站点（比如 `home` → `192.168.9.5:8080`），
**同样不填端口** —— 它们共用同一个入口，靠访问的域名分流。

### 3. DNS：加一条 AAAA 记录指向本机 IPv6

管理后台 → DDNS 域名解析 → 添加记录：

- **记录类型**：`AAAA`
- **域名**：`example.com`
- **子域名**：填 `*`（通配，一次覆盖所有二级域名）
- **IP 来源**：`本地网卡` → 选那块有 IPv6 的网卡（如 `ens18`）
- **服务商**：Cloudflare（Token 需要 `Zone → DNS → Edit`）

保存后它会把本机的 IPv6 写进解析记录。

> 用通配 `*` 最省事：以后加 `xxx.example.com` 不用再来加解析。
> Cloudflare 支持通配（本程序对 Cloudflare 声明了通配能力）。

### 4. 路由器：放行这个端口的 IPv6 入站

这一步在**路由器**上做，不是在 catflap 里：

- 找到「IPv6 防火墙 / IPv6 端口转发 / 安全组」一类设置
- 放行目的端口 `8443`（TCP）到 catflap 那台机器

> 家用路由器默认常开 IPv6 防火墙，不放行的话外网连不进来。
> 这一步做完，IPv6 就通了，**不需要穿透、不需要 UPnP**。

### 5. 证书：签一张通配证书

管理后台 → 证书管理 → 添加证书：

- **来源**：ACME（DNS-01）
- **域名**：`*.example.com` 和 `example.com`
- **DNS 服务商**：选配好的那一家
- 签发成功后绑到反代入口

DNS-01 的验证方式是在域名下写一条 TXT 记录，不要求 80/443 可达 ——
**在没有 IPv4 公网的环境里这是唯一可行的签发方式**。

### 6. 验证

```bash
# 看解析有没有生效
curl -s -H 'accept: application/dns-json' \
  'https://cloudflare-dns.com/dns-query?name=nas.example.com&type=AAAA'

# IPv6 直连（在有 IPv6 的网络下，或用手机蜂窝）
curl -6 -v https://nas.example.com:8443/
```

## 没有 IPv6 怎么办（纯 IPv4 + CGNAT）

IPv4 侧仍然可以用穿透，但**外部端口由 NAT 分配、不受你控制**，所以 URL 必须带端口：

1. 在穿透里给反代入口建一条服务：设备填 catflap 本机 IP，内网端口填 `8443`
2. **务必配置「穿透通道本机端口」**（填一个没被占用的端口）—— 不填的话
   本机端口每次随机，外部端口会一直变，配好的地址很快失效
3. **关掉这条服务的 UPnP** —— CGNAT 下 UPnP 建的映射不生效，开着反而可能在
   建映射失败时拖累穿透（已在 v1.3.1 修复为自动降级，但仍建议关闭）

想要 URL 不带端口，IPv4 环境下只能借助中转：Cloudflare 橙云代理（配源规则改写
回源端口）或 Cloudflare Tunnel。

## 排错

| 现象 | 原因 / 处理 |
|---|---|
| AAAA 记录没写进去 | IP 来源选「本地网卡」时，确认那块网卡确实有全局 IPv6（`fe80:` 开头不算） |
| IPv6 地址通了但连不上 | 路由器 IPv6 防火墙没放行；换手机蜂窝网络测（别在同一局域网内测回环） |
| 访问到的是错的站点 | 站点没挂到默认入口（监听端口别填）；域名拼写/主域名是否匹配 |
| 证书报名字不匹配 | 证书没盖住这个二级域名，签一张 `*.example.com` 通配证书 |
| 打洞端口又变了 | 没配「穿透通道本机端口」，或配的端口被占用（日志里会有提示） |
| UPnP 报「未初始化网关」 | 路由器没开 UPnP，或 CGNAT 下无意义；关掉该服务的 UPnP 改用纯打洞 |
