# v1.5 方案：导航页改版 + Tunnel 独立化

状态：待实施 · 2026-10-15 · 目标版本 v1.5

效果图见评审记录（两种登录状态 + 地址弹窗 + Tunnel 独立页）。

---

## 1. Cloudflare Tunnel 独立成模块

**现状**：Tunnel 面板嵌在「反向代理」页里，和站点表混在一起。

**改为**：

- 新模块 `modules/tunnel/`（配置、进程管理从 proxy 挪过来，进程代码不变）
- `api/tunnel_api/` + `routers/tunnel_routers.go`，跑 `gen_module_imports.py`
- 前端新页面 `pages/Tunnel.tsx`，挂进 registry 与 pageGroups（单独一个功能项）
- 独立的启用开关；proxy 模块里的 Tunnel 配置与面板整体移除
- 兼容：读取旧配置里 `proxy.tunnel` 字段做一次性迁移，迁完删掉旧字段

**验收**：反代页不再出现 Tunnel；Tunnel 页有开关/状态/日志；关掉 Catflap 不留 cloudflared 孤儿进程。

## 2. STUN 应用支持补充地址（v4 / v6 / 内网一个图标）

**现状**：来自 STUN 的应用地址全自动维护，界面提示「仅可修改名称 / 图标 / 颜色 / 分类」，
用户想加 IPv6 或内网入口只能再复制一个图标。

**改为**：

- `App` 增加 `ExtraAddresses { wanV6, lan }`（手动填；STUN 应用也可填）
- `AppAddresses` 合并策略：`WANv4` 仍由穿透自动维护（这是它的本职），
  `WANv6` / `LAN` 优先取手填值，手填为空再回落自动探测
- 编辑弹窗解锁「地址」区：两个字段 + 说明文案（IPv6 建议填 `https://[...]:8443`）
- 普通应用同样能填这三类地址（统一模型，不再区分 STUN/静态）
- 前端：应用图标**长按/右键弹出地址选择**（v4 / v6 / 内网），左键默认走
  `networkPrefer` 选中的那一类

**验收**：一个 NAS 图标覆盖三种入口；穿透地址变了只影响 v4 那一项。

## 3. Sun-Panel 风格分组

**现状**：分组的图标网格存在，但**没有归组的图标悬空显示、没有组头**（见反馈截图：
飞牛NAS 和 github 两个图标孤零零）。

**改为**：

- 所有应用都渲染在某个分组下：有组用组名做节标题；无组的进「未分类」节，
  **不再悬空**
- 节内改成 Sun-Panel 式**卡片网格**：每项一张横卡（图标 + 名称 + 地址类型副标题
  `v4 · v6 · 内网` + 在线状态点），替代现在的纯图标格子
- 分组可折叠；翻页模式下仍按 pagedOrder 排布，卡片只是渲染形态变化
- 设置里保留「显示为卡片 / 图标」的切换，尊重老用户的习惯

**验收**：截图里那种「无组悬空图标」不再出现；任一应用都能看出它属于哪个组。

## 4. 登录入口：右上角，登录后才见后台

**现状**：左下角固定一颗「打开后台」chip，访客也看得见管理入口在哪。

**改为**：

- 顶栏右上角加「登录」按钮（未登录）—— 点击去 `/catflap/` 登录页
- 已登录：右上角显示「后台」入口 + 用户头像/退出（数据来自 `home/config`
  已有的 `authed` 字段，不新增接口）
- **左下角那颗「打开后台」chip 移除**，管理入口只从右上角进
- 登录后锁住的分组才可见（v1.4.1 已实现服务端过滤，此处只接 UI）

## 5. 公开导航页的安全审查结论

导航页是公开的，逐项查过暴露面：

| 项 | 结论 | 处理 |
|---|---|---|
| `GET /home/config` | ✅ 已在服务端过滤锁分组，未登录拿不到组名/应用 | v1.4.1 已做 |
| `GET /home/search-history` | ⚠️ **公开返回全局搜索历史**——访客能看到你搜过什么 | v1.5 改为浏览器 localStorage，或要求登录 |
| `POST /home/icon/fetch` | ✅ 在保护组，SSRF 只能由已登录者触发 | v1.5 再加一层：禁止 fetch 内网地址（10/172.16-31/192.168/127） |
| STUN 应用地址公开 | 设计使然（访客要用服务）；敏感服务放进锁分组即可 | 已有机制 |
| `/catflap/` 登录接口 | ⚠️ 未见失败限速，可被暴力猜密码 | v1.5 加失败限速（同 IP 5 次/分钟） |
| 图标/壁纸上传 | ✅ 保护组 | — |

**总结**：导航页本身不构成攻击面，真正的入口是「穿透出去的端口」和「登录接口」。
v1.5 修 search-history 泄露 + 登录限速这两处。

## 6. 实施顺序

1. **导航页 UI 三件套**（分组卡片化 + 右上角登录 + 后台入口随登录态）—— 纯前端 + `authed` 字段，风险低，先出效果
2. **STUN 应用补充地址**（模型合并策略 + 编辑弹窗 + 地址选择弹层）
3. **search-history 移到 localStorage + 登录限速**（安全收尾）
4. **Tunnel 独立模块**（涉及模块搬迁 + 一次性配置迁移，单独一个版本点发）
