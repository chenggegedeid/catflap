# v1.8 方案：账号体系与安全加固

状态：待实施 · 2026-10-15
触发：安全审查 + 用户提出"增加用户名+密码登录"

---

## 一、安全审查结果

### 1.1 已修：管理后台可被暴露到公网（严重）

**漏洞**（实测整条链跑通）：

```
建站点，后端填 127.0.0.1:<管理端口>
  → 不登录访问 /catflap/    拿到「Catflap 管理后台」页面
  → 调 /api/auth/login       拿到 token（这个接口必须公开）
  → 用 token 调受保护接口     拿到数据（完全接管）
```

穿透服务同理（内网端口填管理端口）。

**关键点**：这不是"未授权访问"（要先能配站点），但**恰恰是用户最容易犯的错**
—— 想在外网访问管理页面时最顺手的做法就是加个站点/穿透指向它，心想"反正还要
登录"。结果把登录页和 `/api/auth/login` 一起挂到公网，谁都能爆破。

**已修**：站点后端、穿透内网端口都禁止指向管理端口（新增+更新都覆盖），
判据是"主机是本机的任一地址 **且** 端口 == 管理端口"。

### 1.2 现状盘点

| 项 | 现状 | 评价 |
|---|---|---|
| 登录限速 | 3 分钟 13 次，**全局** | 能防爆破，但见 1.3 |
| 密码长度 | 最少 8 位 | 偏短，建议提到 12 |
| token | JWT，24h / 记住我 7 天 | 合理 |
| 桌面免登录 | secret 头，CLI 构建为空 | 安全（空 secret 永不匹配） |
| 代理头信任 | `SetTrustedProxies(nil)` | 正确，伪造 XFF 无效 |
| 访问审计 | v1.6 已做 | 能发现扫描 |
| 图标抓取 SSRF | 拨号层挡内网 | 已堵 |

### 1.3 待修问题

**① 登录限速是全局的，不是按 IP**（可用性问题）

管理页一旦暴露被持续爆破，13 次的名额被占满 → **管理员自己也登不进去**。
等于攻击者用很小的代价就能把你锁在外面。

改法：按来源 IP 分桶限速，全局只留一个**宽松很多**的总闸（比如 3 分钟 200 次），
防止换 IP 的分布式爆破。本机 / 白名单 IP 不限速。

**② 密码最短 8 位偏短**

暴露在公网时，8 位纯数字约 1 亿组合，配合限速虽然难破，但用户常填弱密码。
建议提到 12 位，并在设置页给强度提示。

**③ 初始化接口不限制来源**（`docs/decisions/0005` 已记录，是有意取舍）

未初始化期间谁先打开页面谁就能设密码。**装完立刻初始化**是唯一对策，
文档已统一口径。可考虑：只在**首次启动后的 N 分钟内**放开，超时后只允许
本机访问初始化（用已写好的 `middleware.LoopbackOnly`）。

## 二、关于"增加用户名 + 密码登录"

### 结论：**能提升，但别指望它解决主要风险** —— 要看场景

#### 它确实有用的地方

1. **防爆破**：只有密码时，攻击者知道用户名就是固定的（或不存在用户名概念），
   只需猜密码。加了用户名后，攻击者要同时猜中"用户名 + 密码"两个，
   组合空间平方级增长。
2. **多用户**：家里其他人可以有自己的账号，不用共享一个密码；
   也能区分"谁改了什么"（配合访问审计）。
3. **可单独吊销**：某个账号泄露了只改那个，不影响其他人。

#### 它**不能**解决的地方（这点更重要）

- **管理页被暴露到公网**（本次修的漏洞）—— 加不加用户名都一样危险，
  因为 `/api/auth/login` 必须公开。用户名只是让爆破慢一点，不是防住。
- **弱密码** —— 用户名再复杂，密码是 `12345678` 照样破。
- **token 被盗** —— 和用户名无关。

#### 建议：**分两步，先做高性价比的**

| 优先级 | 做 | 理由 |
|---|---|---|
| **P0（必须）** | 按 IP 限速 + 密码提到 12 位 | 直接掐断爆破，成本小 |
| **P1（建议）** | 用户名 + 密码 | 顺带支持多用户与审计归属 |
| **P2（可选）** | 二次验证（TOTP） | 家里场景偏重，但暴露在公网时值得 |
| **P3** | 单点登录 / 只读账号 | 需求不强，先不做 |

### 实施设计（如果做）

**数据模型**（`config/auth.json`）：

```json
{
  "users": [
    {
      "id": "u-1",
      "username": "admin",
      "passwordHash": "$2a$...",     // bcrypt
      "role": "admin",                // admin / viewer
      "createdAt": "...",
      "lastLoginAt": "..."
    }
  ]
}
```

**兼容性**（这是最要小心的）：

现在只有一个密码、没有用户名，直接改成"必须输用户名"会让老用户**登不进去**。
所以：

- 保留一个默认用户名 `admin`（或安装时让用户起一个）
- 老配置迁移：把现有密码哈希挂到 `admin` 名下
- **用户名区分大小写吗？** 建议**不区分**（存小写、比对时转小写）——
  用户自己都记不清大小写，区分只会增加登录失败

**密码存储**：现在用什么哈希要确认，不够强就换成 bcrypt（cost 12）。
bcrypt 自带盐，不用自己管。

**登录接口**：

```
POST /api/auth/login
{ "username": "admin", "password": "..." }
```

老前端传只有 password 的请求 → 当作 username=admin 处理（一段时间后可去掉）。

**别做**：

- 别自己做密码找回（没有邮箱系统，做了也是假的）
- 别加"安全问题"（答案往往比密码还弱）

## 三、其他可以优化的东西

### 3.1 安全类（按性价比排）

1. **按 IP 登录限速**（P0）—— 见 1.3①
2. **密码最短长度 8 → 12**（P0）
3. **登录成功/失败记进审计**（P1）—— 现在审计只记反代的访问，
   不记"谁登录了后台"。把登录事件也记进去，能在访问审计页看到
   "有人从 45.x.x.x 试了 20 次密码"
4. **敏感操作二次确认**（P2）—— 删站点 / 改证书 / 改监听端口时再输一次密码
5. **自动拉黑登录失败的 IP**（P2）—— 复用 v1.6 的封禁表，
   连续失败 N 次就临时封

### 3.2 功能类

1. **流量统计补穿透服务**：现在只采反代的流量，穿透服务直接暴露的那部分
   （不经反代）没统计到。要在 STUN 转发路径上也加采集点
2. **仪表盘加"服务在线率"**：最近 24h 各服务的可用比例
3. **反代站点健康检查**：定时探后端，挂了就在卡片上标红并通知
4. **配置导出/导入**：换机器时一键搬走全部配置（含站点、证书、穿透服务）
5. **证书到期前主动推送**：现在有事件（cert.expiring），但要有规则才发；
   建议**默认建一条规则**，否则用户不知道要自己配

### 3.3 体验类

1. **反代与穿透的操作统一**（v1.7 已做列表卡片，还可继续）：
   - 两边的"添加"表单字段顺序与措辞对齐
   - 共用同一套状态徽章组件
2. **首次使用引导**：装完不知道先干什么（初始化 → 加入口 → 加站点）。
   可以做一个 3 步指引
3. **移动端适配**：管理页在手机上能看，但弹窗有点挤

# v1.9 补充审查（设备共用重构）

## 审查了什么

这版新增了：公共设备模块、端口转发（独立功能）、入口多端口、Scheme 三态、
设备页与端口转发页。逐项过了一遍输入校验与鉴权。

## 发现并修的问题

**① 端口转发完全没有校验（严重）**
加了 Forwards 类型和迁移，但漏了校验逻辑 —— 而它能监听任意端口、转发到
任意目标。意味着 `ListenPort=3791` 会顶掉后台监听，`Target=127.0.0.1:3791`
会把管理后台挂到公网（正是 v1.8 修的漏洞，这条新路径没堵）。
已补：监听端口不能是后台端口/不能撞默认入口/不能重复；目标不能指向后台端口；
协议只认 tcp/udp。10 条攻击用例钉住。

**② Scheme 没有白名单**
任意字符串都能存，不认识的值会走 default 当 auto 处理 —— 看着能用，
但用户以为自己设了某个协议，实际行为不同。**这种悄悄降级比报错难查**。
已改成只认 auto/http/https，选 https 时自动置 HTTPS=true（否则一个入口都挂不上）。

**③ 删设备会让穿透服务静默失效**
穿透服务按 deviceId 关联，设备一删就成孤儿（配置还在、但 hydrate 匹配不到
设备 → 不再运行）。用户只会看到"服务不工作了"却看不出原因。
已改成删除前检查，有服务就拒绝并列出是哪些。

## 确认没问题的

- 新接口（device/*、proxy/forward）都挂在受保护路由组，需要 token
- 设备表不含任何凭据，暴露出去只是内网拓扑（也已受保护）
- 流量统计的 names 只含服务名，不含 backend 地址等细节
- 登录审计仍然不记密码（这版没动）

## 仍然成立的既有结论

- 管理后台不能通过站点后端/穿透端口/端口转发暴露（三处都堵了）
- 初始化接口不限制来源，装完要立刻初始化（见 0005）
- 登录限速按 IP，本机不限速
