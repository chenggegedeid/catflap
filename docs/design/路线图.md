# 功能路线图

原则：**每个版本都能单独发布、单独回退。** 不做「憋一个大版本」。
版本号遵循[语义化版本](https://semver.org/lang/zh-CN/)，tag 形如 `v1.0.0`（**不带后缀**）。

> 为什么不带后缀：程序内部 `releaseVersion()` 会取最后一个 `-` 之后的部分来解析版本，
> 带后缀会解析错。预发布请用 GitHub Release 的 Pre-release 勾选项。

---

## v1.0.0 —— 焕新（当前）

**目标：功能与上游对齐，把壳和底座全换掉。** 不新增业务功能，这样首版可验证、可回滚。

| 类别 | 内容 |
|---|---|
| 品牌 | 更名 Catflap、换图标、改后台路径（`/linkstar/` → `/catflap/`）、换发布资产名 |
| 安全 | 首次初始化限定本机；移除更新源的第三方 API 镜像；收紧 `config/` 权限；systemd 加固示例 |
| 架构 | `core/component`、`core/provider`、`core/bus` 三层扩展点 |
| 工程 | CI 与发布流水线、版本号统一注入、治理文件（NOTICE / CONTRIBUTING / SECURITY / CHANGELOG） |

**验收**：现有功能全部回归通过；从 LinkStar 拷 `config/` + `data/` 过来能直接用。

## v1.1.0 —— 补齐「内网穿透工具」的基本盘

这几项是目前这一类工具的事实标准，缺了会被认为「功能不全」。也是上游 `todo.md`
自己和方向一致的部分。

| 功能 | 新组件 | 说明 |
|---|---|---|
| **IPv6 ↔ IPv4 端口转发** | `modules/portfwd` | 替代「装个 socat」的做法：规则表 + 会话统计 + 与穿透的服务索引打通 |
| **计划任务** | `modules/task` | 定时执行 Webhook、重启服务、同步 DDNS。直接消费 `core/component` 的 `Schedulable` 接口 |
| **Web 服务子规则** | 扩展 `modules/proxy` | 按 Host / Path 分流到多个内网服务，含规则优先级与冲突检测 |
| **DDNS / ACME 服务商扩充** | 走 `core/provider` | 现有 Cloudflare / 阿里 / 腾讯 / 华为 / 百度 / NameCheap / NameSilo，补到 10+ |
| **内置实测可用 STUN 分组** | 扩展 `modules/stun` | 内置一批实测稳定的公共 STUN，并支持「一键测速并启用可用项」 |

## v1.2.0 —— 顺手能用的东西

| 功能 | 说明 |
|---|---|
| WOL 唤醒 | 从面板唤醒内网设备 |

## v1.3.0 —— 差异化（这三条是我们独有的）

它们不是「别人有我们也要有」，而是这个项目**值得单独存在**的理由。

| 功能 | 说明 |
|---|---|
| **打洞诊断报告** | 打不通时不只报「失败」，而是给出原因链：NAT 类型是什么、哪一步超时、建议改用哪个 STUN 或换中继。目前这个品类的工具在这一步基本都是「自己猜」 |
| **上游健康检查 + 故障转移** | 洞断了自动切到备用上游/中继。依赖 `core/bus` 的 `TopicTunnelDown` |
| **安全中心** | TOTP 双因素、子账户与权限、配置字段级加密（`config/` 里的凭据不再是明文） |

## 明确**不做**的事

写出来是为了省掉重复讨论：

- **不做账号体系与云端**：这个项目的定位是「你自己的机器、你自己的服务」，
  配置与凭据只存在本机。
- **不做 Clash/V2Ray 那类代理协议**：那是另一个品类，混进来会让合规与技术面都复杂化。
- **不逆向闭源竞品**：功能设计可以参照（思想不受著作权保护），代码与图标一律不碰。
  见 [`../compliance/`](../compliance/)。
- **不引入许可不兼容的依赖**：特别是 GPL-2.0（与本项目的 GPL-3.0 不兼容）。
