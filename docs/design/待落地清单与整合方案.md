## 二、没落地的（按依赖关系分组）

### A 组：反代重构 —— 建议一次做完

这三项都在改反代，**分开做会互相打架**（改了站点结构再改端口，等于改两遍），
所以放在一起。

**A1. 设备 → 服务两层结构**（已确认，见 `反代设备与服务结构-v1.9方案.md`）
- 站点归入设备（按 backend 的 IP 自动迁移，不用手动整理）
- 设备可命名（"群晖 NAS"），界面与穿透的设备列表一致
- 流量统计显示「群晖 NAS · 照片库」而不是「站点 #3」

**A2. 入口支持多个端口**
- 现在入口只能配一个 HTTP + 一个 HTTPS
- 改成可以配多个（如内网走 80、外网映射走 8080，同一批站点两个端口都能访问）
- 要多个端口就在入口加，**不用每条站点各填一遍**

**A3. 服务只选协议，端口跟着入口走**
- 加服务时不用填端口，只选 HTTP / HTTPS / 自动
- 入口配了证书时**默认 HTTPS**
- 原来"站点独占端口"保留，但收进高级选项（端口转发这类场景才用得到）

### B 组：可观测性

**B1. 站点健康检查**（依赖 A1：健康检查挂在"服务"上才有意义）
- 定时探后端，挂了在卡片上标红 + 可选通知
- 现在后端不可达只能靠用户自己访问失败才发现

**B2. 服务在线率**（依赖 B1）
- 仪表盘显示各服务最近 24h 的可用比例

**B3. 证书到期默认建一条通知规则**
- 现在有 `cert.expiring` 事件，但**要用户自己配规则才发**，不配就静默过期
- 建议首次配置证书时自动建一条"到期前 7 天提醒"

### C 组：运维便利

**C1. 配置导出 / 导入**
- 换机器时一键搬走（站点、证书、穿透服务、DDNS）
- 证书私钥要处理好：导出时可选"含密钥"（迁移用）或"不含"

**C2. 首次使用引导**
- 装完不知道先干什么（初始化 → 加入口 → 加设备 → 加服务）
- 3 步指引，可跳过

**C3. 移动端适配**
- 管理页手机上能看，但弹窗偏挤

### D 组：安全加固（P2，性价比中等）

**D1. 敏感操作二次确认** —— 删站点 / 改证书 / 改监听端口时再输一次密码
**D2. 自动拉黑登录失败的 IP** —— 复用 v1.6 的封禁表，连续失败 N 次临时封

## 四、几个取舍，需要你定

**① 反代设备表要不要和穿透共用？**
建议**不共用**（反代不能依赖 stun，那条原则前面坚持过几次）。
代价是同一台机器两边各一条记录。可以后续加"从穿透导入"按钮。

**② 站点可以不挂设备吗？**
建议允许，收在「未分组」。有人就是想配端口转发、后端填域名而不是 IP。

**③ 配置导出含不含证书私钥？**
建议**默认不含**，导出时给一个开关"含密钥（用于迁移到新机器）"。
含密钥的文件等于凭据，不该是默认行为。

**④ 健康检查的探测频率？**
建议默认 5 分钟一次，只探 TCP 连通（不探 HTTP），
避免给内网服务造成负担 —— 也避免某些服务把健康检查当攻击。
