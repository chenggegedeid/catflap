# 日志规范：命名、分类与查阅

状态：已定 · 2026-10-15
适用范围：整个项目的日志相关命名、文件组织、界面分类

---

## 1. 统一叫「日志」

**不再出现「运行日志」这个词**。理由：它暗示还存在"非运行日志"，
但实际上这个项目只有一种日志（程序输出），加限定词反而让人以为另有东西。

| 旧说法 | 统一为 |
|---|---|
| 运行日志 / Runtime log | **日志** |
| 访问日志 / Access log | **访问日志**（这个是**另一类数据**，见下） |
| Webhook 日志 | **通知日志** |

## 2. 两类东西，别混

这是分类的基础 —— 两者长得像，但**用途和存储方式完全不同**：

| | 日志 | 访问记录 / 流量 |
|---|---|---|
| 是什么 | 程序说"我做了什么" | 请求本身的统计 |
| 谁写的 | 各模块 `logrus.Info/Warn/...` | 反向代理采集 |
| 存在哪 | `logs/<日期>/info.log`、`err.log` | `data/traffic/<日期>.jsonl` |
| 形态 | 文本行，给人读 | 结构化（JSON），给界面画图 |
| 保留 | 按天分目录，长期 | 90 天后自动清理 |
| 界面 | 「日志」页 | 仪表盘 / 访问统计页 |

**判断标准**：需要画图的进 `data/`，需要人读的进 `logs/`。

## 3. 日志按「模块」分类

现在的日志行里有文件名和函数名，但没有**模块归属** —— 想把"穿透的事"
单独看一眼，只能靠 grep 文件名猜。

### 3.1 分类方式：从调用栈自动推，不手工标

每条日志加一个模块标签，**由 logrus 的 Hook 从 `entry.Caller` 的包路径推出来**：

```
github.com/chenggegedeid/catflap/modules/stun/scheduler.go:114
                                    ↑ modules/ 后面那一段就是模块名 → "stun"
```

`modules/proxy/xxx.go` → `proxy`，`core/logrus.go` → `core`，
`api/stun_api/` → `stun`（按 api 的模块名归一），`routers/` → `router`。

**为什么不手工传字段**：手工标就得改几百处 `logrus.Info` 调用，
而且新代码一定会漏。从调用栈推是零成本的，且**天然不会漏**。

### 3.2 日志格式

```
[时间] [级别] [模块] [文件:行] 内容
```

实际例子：

```
[2026-10-15 17:20:31] [info] [stun] [scheduler.go:114] 服务「飞牛NAS」打洞成功 外部端口 35545
[2026-10-15 17:20:33] [warn] [proxy] [accesslog.go:53] 来源 45.155.204.11 被全局封禁拒绝
[2026-10-15 17:20:35] [error] [ddns] [ddns_syncrecord.go:124] Cloudflare 同步失败：Authentication error
```

模块标签是**第四段**，grep 起来很直接：`grep '\[stun\]' info.log`。

### 3.3 模块名清单（与功能页对齐）

| 模块 | 管什么 |
|---|---|
| `stun` | 内网穿透、打洞、UPnP |
| `proxy` | 反向代理、站点、访问日志 |
| `tunnel` | Cloudflare Tunnel |
| `ddns` | 域名解析同步 |
| `cert` | 证书签发与续期 |
| `notify` | 通知发送 |
| `traffic` | 流量采集 |
| `home` | 导航主页 |
| `auth` | 登录与鉴权 |
| `task` | 计划任务 |
| `wol` | 网络唤醒 |
| `update` | 自动更新 |
| `core` | 框架层（组件、事件总线、日志本身） |
| `router` | 路由装配 |
| `other` | 推不出模块的（理论上不该有） |

**`other` 出现就说明有代码没按约定放**，是个自检信号。

## 4. 界面上的分类：折叠 + 异常计数（用户要求的形态）

**默认不展开内容**，只按分类列一行摘要：分类名 + 条数 + **异常（warn/error）数**。
点一下才展开看详情。

```
┌────────────────────────────────────────────────────────────┐
│ 日志                                [级别 ▾] [日期 ▾] 🔍   │
├────────────────────────────────────────────────────────────┤
│ ▸ 穿透        1,204 条   ⚠ 3  ✕ 1                          │
│ ▸ 反向代理    8,912 条        ✕ 12                         │
│ ▸ 域名解析      310 条   ⚠ 1                                │
│ ▸ 证书           48 条                                      │
│ ▸ 通知           26 条        ✕ 2                           │
│ ▸ 流量           18 条                                      │
│ ▸ 系统 / 框架     92 条   ⚠ 2                                │
└────────────────────────────────────────────────────────────┘
```

点「穿透」那一行展开：

```
▾ 穿透        1,204 条   ⚠ 3  ✕ 1
  [2026-10-15 17:20:31] [info]  打洞成功 外部端口 35545
  [2026-10-15 17:22:04] [warn]  UPnP 不可用，转为纯打洞
  [2026-10-15 17:25:11] [error] 打洞失败：网关拒绝
  ...（展开后仍按 limit 截断，默认 200 条）
```

### 设计要点

- **折叠态只给数字**：一眼看出"哪个模块在闹"
- **异常数用颜色区分**：warn 黄、error 红。0 就不显示（不给视觉噪音）
- **展开才读文件**：折叠态的数字从轻量统计来，展开才读完整日志 ——
  否则一进页面就把几个 log 文件全读一遍，没必要
- **展开后仍限条数**（默认 200，可调），并显示"共 N 条，展示最新 200"
- 排序：**有异常的排前面**，其次按条数。用户打开这一页的动机通常是
  "哪儿出问题了"，不是"哪个模块话多"

### 摘要数字怎么来

`LogSummaryView`（新接口）：扫当天目录，按模块 + 级别统计条数，
**只回数字不回内容**。文件不大（当天日志通常几 MB），一次扫完几百毫秒，
且结果可以缓存 30 秒 —— 用户在页面上反复点分类不会每次都重扫。

### 分类清单（与模块对齐）

分类名直接用模块名，界面上显示中文：

| 分类显示 | 模块 | 管什么 |
|---|---|---|
| 穿透 | `stun` | 打洞、UPnP、公网地址 |
| 反向代理 | `proxy` | 站点、转发、门禁 |
| Tunnel | `tunnel` | Cloudflare Tunnel |
| 域名解析 | `ddns` | 解析同步 |
| 证书 | `cert` | 签发与续期 |
| 通知 | `notify` | 渠道发送 |
| 流量 | `traffic` | 采集与落盘 |
| 导航页 | `home` | 门户 |
| 安全 | `auth` | 登录、鉴权、封禁 |
| 计划任务 | `task` | 定时任务 |
| 系统与框架 | `core` / `router` / `other` | 框架层 |

`.err.log` 保持现有语义：error 及以上的副本，方便直接看"出过什么错"。

## 5. 实施清单

1. `core/logrus.go`：从 Caller 推模块名（✅ 已完成，13 个用例的单测通过）
2. `api/system_api/log_list.go`：`parseLog` 多解析一段模块；
   `LogListView` 支持 `module` 参数；新增 `LogSummaryView`（分类计数）
3. 前端「日志」页：改成折叠式（分类行 + 异常数），点开才拉详情
4. 全项目把「运行日志」的说法统一成「日志」

## 6. 不做什么

- **不做日志级别的手工分类**（"业务日志/技术日志"）：机器分不清，落地必然拍脑袋
- **不引日志框架**（zap / zerolog）：logrus 够用，换框架要改几百处调用，
  换来的性能提升在家里几个服务的量级上看不出来
- **不在折叠态加载日志内容**：那是"打开页面先卡一下"的常见来源
