# 0006. 移除「上游区」目录约束，清理上游遗留文件

- 状态：已采纳
- 日期：2026-10-15
- 影响面：仓库根目录、`docs/`、`CONTRIBUTING.md`、`docs/README.md`
- 取代：[0004](0004-改用自有-go-module-名.md) 里「保留上游路径」的残留理由

## 处境

项目早期定了「上游区冻结」：`docs/about.md`、`docs/快速上手.md`、`docs/部署与升级.md`、
`docs/img/`、根目录的 `AGENTS.md`、`BUILD.md`、`Taskfile.yml`、`ads.md`、`todo.md`、
`icon_*.png`、`lICON.PNG`、`linkstar.xmind`、`test/` 等文件留在上游原始路径，
**哪怕看着该整理也不动**。

理由只有一个：这些路径是上游 `ZluxYao/LinkStar` 的原始位置，动一个，将来
`git merge upstream/main` 就要多一次手工修复。为了长期可合并，接受眼前的乱。

## 前提消失

[ADR-0004](0004-改用自有-go-module-名.md) 之后本项目不再与上游合并——
历史重建、module 改名、改写清单进 `NOTICE`。上游更新改为人工阅读借鉴。
于是「为合并保留路径」的理由不成立，只剩「路径的约定俗成」，这不值得 36 MB
的实验代码和一堆 LinkStar 时代的图标来换。

## 决定

- **归档**：`docs/about.md`（上游原 README）→ `docs/upstream/about.md`；
  `docs/快速上手.md`、`docs/部署与升级.md` 内容是本项目的、仍在使用，
  → `docs/guides/`（与 IPv6 指南同区）。
- **删除**：
  - `test/`（36 MB，上游的实验程序，不参与产品构建，无任何代码引用）；
  - `icon_64.png`、`icon_256.png`、`lICON.PNG`（品牌资产已归 `branding/`）；
  - `docs/img/home.jpg`、`stun.png`、`qq.png`、`wx.png`（LinkStar 时代的截图，
    品牌已换，留着只会让人困惑）；
  - `README.en-US.md`（内容还是 LinkStar 的，属于错误信息而非翻译，
    将来若需要英文版按新界面重写）。
- `AGENTS.md`、`BUILD.md`、`Taskfile.yml`、`build/` **保留**：内容早已改写成
  本项目的，且编译和协作在用。
- `docs/README.md` 的「上游区 / 本项目区」规则随之撤销，改为一份普通的文档索引。

## 代价与风险

1. 若哪天真要回头合并上游，这些文件的路径差异会逐个冒出来。
   接受：本就不打算合并（见 ADR-0004）。
2. `git` 里被删文件的历史仍可通过历史提交找到，内容没丢。

## 什么情况下应该重新考虑

决定恢复与上游的 `git merge` 同步时——那时得把这些路径按上游原样恢复，
并重新评估每一处改写。
