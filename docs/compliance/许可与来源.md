## 商标边界（重要）

**GPL 授予著作权许可，不授予商标权。** 这是两件独立的事，很容易被混淆。

因此本项目：

- **不再使用** `LinkStar` 这个名称与上游图标；
- 使用自绘的名称 **Catflap** 与自绘图标（见 [`../../branding/`](../../branding/)）；
- 在 README 顶部明确声明这是**衍生项目**，与上游之间**不存在**官方、赞助或背书关系；
- 不主张 `LinkStar` 的任何权利，也不允许别人把本项目与上游混为一谈。

反过来说：如果你用本项目二次分发，**你必须换掉 Catflap 这个名称与图标** ——
因为商标权不随 GPL 一起授予。许可允许你改代码，名称与图标不在此列。

## 第三方代码政策

### 可以引入

| 来源 | 许可 | 条件 |
|---|---|---|
| 上游 LinkStar | GPL-3.0-or-later | 直接合并即可，保留声明 |
| MIT / BSD / Apache-2.0 的项目 | 宽松 | 允许，但**必须在 `NOTICE` 里补上其版权声明** |
| Apache-2.0 | 兼容 GPL-3.0 | 同上；注意其专利条款 |

### 不可以引入

| 来源 | 原因 |
|---|---|
| **GPL-2.0**（例如 `snltty/linker`） | **与 GPL-3.0 不兼容**，代码不能借。设计思路可以参照 |
| **闭源 / 加壳的二进制**（例如 Lucky v2/v3） | 无法验证、逆向违规。名称、图标、代码一律不碰 |
| 来源不明或许可缺失的代码片段 | 不引入 |

### 参照设计 vs 复制代码

**功能思想不受著作权保护，具体表达受保护。** 所以：

- ✅ 看到某个工具「支持按时间段自动启停服务」，自己也实现一个 —— 可以；
- ❌ 把它的那段实现抄过来（哪怕改成别的语言逐句翻译）—— 不可以；
- ✅ 参照它的**交互流程**来设计自己的界面 —— 可以；
- ❌ 用它的名称、图标、文案 —— 不可以（可能同时涉及商标与著作权）。

实践中把这条简化成一句话：**看懂它想解决什么问题，然后自己写。**

## 收到许可相关质询时

1. 先核对上游 `NOTICE` 与 `LICENSE` 是否完整保留；
2. 若涉及商标（要求改名 / 下架），这通常与代码许可无关，按对方要求处理，
   并在 `CHANGELOG` 记录；
3. 若涉及第三方代码归属，补上声明即可，不要辩解「我以为那是公有领域」。
